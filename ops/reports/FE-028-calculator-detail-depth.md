## 구현 결과

### 세부 행사와 예상 인원

- 기존 5단계와 `kids`, `parents`, `meeting`, `anniversary`, `other` 행사 ID를
  유지하면서 1단계 안에 대분류별 필수 세부 행사를 추가했다.
  - 돌잔치·백일: 백일, 돌잔치, 키즈 파티
  - 환갑·칠순·팔순: 환갑, 칠순, 팔순, 부모님 생신, 퇴임·은퇴 기념
  - 결혼 준비: 상견례, 약혼식, 소규모 예식
  - 기념일·생신: 생일, 결혼기념일, 가족 기념일
  - 기타 가족행사: 가족모임, 추모·제례, 송년·신년 모임, 그 밖의 가족행사
- `state.eventDetail`을 추가하고 대분류나 세부 행사를 바꾸면 이전 공간,
  공간 세부 조건, 준비 서비스 상태를 초기화한다.
- 기존 인원 구간 버튼은 제거했다. `type=number`, `min=1`, `max=500`,
  `step=1` 입력과 `10/20/30/50/100명` 바로가기로 대략적인 예상 인원을
  받는다.
- 검색 컨텍스트의 `guests=30` 같은 구간값을 실제 30명으로 자동 계산하지
  않도록 초기 예상 인원은 항상 비우고 사용자가 다시 입력하게 했다.
- 0명·501명·소수·지수 표기는 거부하고 `aria-invalid`, 한국어 오류 상태,
  다음 버튼 비활성으로 전달한다.

### 다섯 공간의 식비와 계산

- 프라이빗 룸은 기존 음식점 유형 5개와 1인 식비를 모두 필수로 유지했다.
- 호텔·연회장, 대관 파티룸, 자택·출장, 야외·가든은 기존 이용 방식과 함께
  같은 1인 식비 4개 범위를 필수로 받는다.
- 모든 공간에서 사용자가 선택한 식비 범위를 예상 인원에 한 번만 곱한다.
  행사 프로필의 암묵적 식비 기본값은 제거했다.
- 비프라이빗 공간은 `선택 식비 × 예상 인원 + 기본 공간 범위 + 이용 방식
  범위`, 프라이빗 룸은 `선택 식비 × 예상 인원 + 프라이빗 룸 범위`로
  계산한다.

### 결과·저장·검색 계약

- 결과 요약에 대분류와 세부 행사, 예상 인원, 공간과 음식/이용 방식,
  1인 식비를 한국어로 표시한다.
- 비용 내역에도 식비와 공간 조건을 분리해 표시하고 공유 문구에 세부 행사,
  예상 인원, 1인 식비를 반영한다.
- `calculator-state` 키와 `{ ...state, ...result }` 저장 형식을 유지해
  `eventDetail`, 정확한 `guests`, `spaceDetails.mealBudget`이 함께 저장된다.
- 공개 업체 검색에는 기존 필드만 유지한다. 예상 인원은 기존 검색 구간으로
  변환하고 `eventDetail`, 음식 유형, 공간 이용 방식, 식비는 쿼리에
  추가하지 않았다.
- 체크리스트 링크에는 기존 계약대로 예상 인원을 전달한다.
- 준비 계획용 가정이며 확인된 시세·전국 표본·실제 견적이 아니라는 안내를
  유지했다.

## 화면·뷰포트 검증

### 390×844

- `clientWidth=390`, `scrollWidth=390`, 가로 넘침 0
- 표시된 버튼·입력·링크의 최소 높이 44px
- 세부 행사 미선택 시 다음 비활성, `기타 가족행사 → 가족모임` 선택 뒤 활성
- 예상 인원 0·501 입력 시 `aria-invalid=true`와 다음 비활성, 37 입력 시
  `aria-invalid=false`와 다음 활성
- 호텔 이용 방식만 고르면 다음 비활성, 1인 식비까지 고르면 활성
- 37명, 호텔 연회 진행 포함, 1인 5만~8만 원 예시:
  - 식사 185만~296만 원
  - 장소 100만~400만 원
  - 합계 285만~696만 원
  - 식비를 예상 인원에 한 번만 곱한 값과 일치
- 결과 요약에 `기타 가족행사 · 가족모임`, `37명`,
  `호텔·연회장 · 연회 진행 포함`, `5만~8만 원` 표시
- 업체 검색 링크는 기존 키만 사용하고 예상 37명을 기존 `50명 이하`
  필터로 변환했다. 체크리스트 링크에는 `guests=37`을 유지했다.
- 결과 저장 버튼 뒤 `이 기기에 계산 결과를 저장했습니다.` 상태 메시지 확인
